# Архитектура

```text
Ruby / JS / TS source
        │
        ▼
CodeGraph 1.6.2: Tree-sitter + cross-file resolution
        │
        ▼
.codegraph/codegraph.db (SQLite, schema 11)
        │ read-only transaction
        ▼
archcheck: YAML selectors → forbidden direct edges → text / JSON / exit code
```

## Почему готовый граф

Парсинг, разрешение вызовов, импортов и наследования принадлежат CodeGraph.
В Go реализованы конфигурация, адаптер, правила и отчёт. Это позволяет начать с
Ruby и JS без разработки своих языковых frontend'ов. Полноценные CFG/DFG и taint
analysis не считаются свойствами этого структурного графа.

## Адаптер и доказательства

`scan` проверяет версию upstream, запускает `sync` без shell-интерполяции аргументов,
затем открывает базу с `mode=ro` и `query_only`. Все запросы входят в одну транзакцию.
Адаптер требует `project_metadata.index_state=complete`,
`indexed_with_version=1.6.2` и максимальную версию схемы 11.

Читаются `files`, `nodes`, `edges`, `unresolved_refs` и метаданные.
SHA-256 каждого индексированного файла сравнивается с `content_hash`.
Удалённые, изменённые и выходящие за корень через путь или симлинк файлы блокируют scan.
Ошибки парсинга блокируют результат. Неизвестные endpoints связи блокируют scan.

Узлы загружаются в память, принадлежность каждому селектору рассчитывается один раз.
Связи читаются потоком и проверяются по membership-наборам. Ограничение первой версии:
память растёт с количеством узлов и найденных нарушений; большие монорепозитории
пока не профилированы.

## Результат

`violations` означает найденную запрещённую связь.
`no_observed_violations` означает отсутствие таких связей в доступном графе;
неразрешённые ссылки могут скрывать вызовы. Они учитываются в coverage и предупреждениях.
`blocked` означает, что результат нельзя принять как успешную проверку.

В строгом режиме неразрешённые ссылки блокируют scan. Синхронизацию нельзя пропускать.
В режиме `--no-sync` SHA-256 проверяет известные файлы, но не обнаруживает новые:
это явно указано в warnings, а не маскируется под полную свежесть.

Selectors объединяют поля через AND, варианты одного поля через OR.
`symbols` сопоставляет glob с простым и qualified-именем. Проверки транзитивности,
исключения, автоматический вывод архитектуры и выполнение arbitrary SQL отсутствуют.
Конфигурация не содержит исполняемого кода.

Детерминированная сортировка findings: файл, строка, правило, тип связи, endpoints.
JSON идёт в stdout; сообщения дочернего индексатора и диагностические ошибки — в stderr.
Коды 0/1/2 документированы в README.

## Проверка совместимости

`integration/package.json` фиксирует CodeGraph 1.6.2; lockfile фиксирует транзитивные пакеты.
При обновлении адаптера сначала прогоняются реальные JS/Ruby-индексы, затем меняются
константы совместимости и документация. Схема upstream — внутренний контракт,
поэтому неизвестная версия не принимается на основании похожих таблиц.
