# archcheck

Локальная утилита на Go для проверки архитектурных правил в Ruby и JS/TS-проектах.
[CodeGraph](https://github.com/colbymchenry/codegraph) строит граф кода;
archcheck проверяет запрещённые связи между каталогами и символами.

**Статус: первый работающий прототип.** Проверен с CodeGraph **1.6.2**, схема SQLite **11**.
Это проверка структурного графа, а не полноценный анализ потоков данных / CPG.

## Быстрый старт

Требуются Go 1.26.5+ для сборки и CodeGraph 1.6.2 для индексирования.

```sh
go install github.com/dapi/archcheck/cmd/archcheck@latest
npm install -g @colbymchenry/codegraph@1.6.2
```

Из корня своего проекта:

```sh
# Индексирование без телеметрии. Подключение MCP не требуется.
DO_NOT_TRACK=1 codegraph init --yes

# Для Rails; для JS используйте --preset js.
archcheck init --preset rails
# Отредактируйте archcheck.yaml под структуру и правила своего проекта.
archcheck scan
```

`scan` по умолчанию запускает `codegraph sync`, затем читает индекс в режиме read-only.
Утилита отключает телеметрию и проверку обновлений для дочерних процессов CodeGraph
через `DO_NOT_TRACK=1` и `CODEGRAPH_TELEMETRY=0`. archcheck не имеет сетевых вызовов.

Шаблоны выражают пример архитектурного решения, а не универсальный стандарт:
в Rails контроллеры обращаются к `app/clients` через сервисный слой;
в JS `src/ui` не обращается к `src/domain` напрямую. Замените пути и правило,
если архитектура вашего проекта другая. Если селектор не нашёл ни одного узла,
проверка блокируется вместо молчаливого успеха.

## Правила

```yaml
version: 1
rules:
  - id: controllers-no-payment-gateway
    description: Платёжный шлюз вызывается через сервисный слой.
    from:
      paths: ["app/controllers/**"]
      languages: [ruby]
    to:
      paths: ["app/clients/**"]
      symbols: ["**/*PaymentGateway.charge"]
    edges: [calls]
```

Каждое правило запрещает **прямую** связь `from → to` выбранных типов.

- `paths` — glob по пути относительно корня, разделитель `/`, `**` включает вложенные каталоги.
- `symbols` — glob по имени или полному `qualified_name` из CodeGraph.
- `kinds` — точные типы узлов, например `class`, `method`, `function`, `file`.
- `languages` — точные имена языков CodeGraph: `ruby`, `javascript`, `typescript`, `tsx`, `jsx`.
- Внутри поля варианты объединяются через OR, между полями — AND.
- Поддерживаемые связи: `calls`, `imports`, `extends`, `implements`, `references`, `instantiates`.

Синтетические связи `calls` с `metadata.synthesizedBy=interface-impl` исключаются:
это переходы индексатора от объявления интерфейса к реализации для обхода графа.
Их количество отражается в `coverage.excluded_dispatch_edges`. Реальные импорты,
`implements` и остальные связи остаются предметом проверки.

Импорт файла и импорт его экспортированного символа могут быть отдельными связями:
отчёт сохраняет обе. Повторяющиеся идентичные связи удаляются из отчёта.

ИИ-агент может подготовить YAML по структуре проекта и принятым ограничениям.
Правило следует проверить на примере с нарушением и после его исправления.
Сам `archcheck scan` работает без модели, API-ключей и MCP.

## CLI и CI

```sh
archcheck scan --project /path/to/project --format json
archcheck scan --strict
archcheck scan --codegraph /path/to/codegraph --timeout 2m
```

| Код завершения | Значение |
|---|---|
| `0` | В доступном графе нет наблюдаемых нарушений |
| `1` | Найдены запрещённые связи |
| `2` | Проверка заблокирована: ошибка правил, индекса, парсинга или пустой селектор |

`--strict` также блокирует проверку при неразрешённых ссылках. В динамическом Ruby
они встречаются даже у корректного кода: это честный сигнал о неполноте анализа,
а не свидетельство архитектурного нарушения.

`--no-sync` предназначен для отладки уже созданного индекса: хеши индексированных
файлов проверяются, но новые файлы могут быть пропущены. В строгом режиме флаг запрещён.
Неполный (`index_state != complete`), устаревший или несовместимый индекс не принимается.

Минимальные шаги CI после установки обеих утилит:

```sh
DO_NOT_TRACK=1 codegraph init --yes
archcheck scan --format json > archcheck-report.json
```

Добавьте `--strict`, если хотите блокировать CI и при пробелах в разрешении ссылок.

## Границы первой версии

- Только прямые связи. Транзитивные запреты, baseline, исключения и SARIF пока не реализованы.
- Нет taint analysis, доказательства отсутствия уязвимостей или анализа значений переменных.
- Динамические вызовы, Ruby-метапрограммирование и особенности фреймворков ограничены точностью CodeGraph.
- Проверка охватывает файлы, выбранные индексатором; исключения CodeGraph и `.gitignore` сохраняют силу.
- Адаптер к внутренней SQLite-схеме привязан к проверенной версии upstream; другая версия требует проверки совместимости.
- Проверка предполагает отсутствие параллельного редактирования исходников во время scan.
- Go-бинарник — проверяющий слой. CodeGraph поставляется отдельно со своим runtime и ядром Rust.

## Разработка

```sh
go test ./...
go vet ./...
go build -o bin/archcheck ./cmd/archcheck
npm ci --prefix integration
python3 integration/run.py
```

Интеграционные тесты строят реальные индексы JS, Ruby и TypeScript во временных каталогах,
проверяют нарушения, чистый результат, синхронизацию новых файлов, JSON, коды завершения,
неразрешённые ссылки, синтетические переходы интерфейсов и отказ на устаревшем индексе.

## Локальная верификация на своём проекте

[Скрипт проверки](scripts/verify-project.py) индексирует выбранные исходники в
изолированном локальном снимке, не запускает приложение и не загружает код в сеть.
Требуется Python 3; CodeGraph и archcheck должны быть уже установлены.

```sh
python3 scripts/verify-project.py /path/to/project \
  --include src --metadata package.json --metadata tsconfig.json \
  --codegraph /absolute/path/to/codegraph \
  --archcheck /absolute/path/to/archcheck
```

Указывайте только существующие metadata-файлы; для Ruby они не обязательны.
Повторяемые `--include` и `--exclude` задают scope, `--rules` принимает ваши правила.
Если собственный код находится в каталоге, который CodeGraph исключает по имени
(например, `vendor`), можно явно разрешить его через `--unignore-dir vendor`.
Это касается только выбранных исходников снимка.

Скрипт сверяет список выбранных файлов с индексом, проверяет контрольную запрещённую
связь по независимому SQL-запросу, отсутствие другой связи, строгий режим,
пустой селектор и устаревший индекс. Результаты находятся в игнорируемом
`.archcheck-verification/<timestamp>/` внутри проекта. Каталог содержит приватный
снимок и подробные отчёты; не публикуйте его. `summary.json` отдельно сообщает
непроиндексированные файлы и неразрешённые ссылки. Контрольные правила служат
проверкой утилиты, а не оценкой архитектуры проекта.
